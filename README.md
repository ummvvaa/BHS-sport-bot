# Beta High School — бот записи на спортивные секции

Telegram-бот на Python (aiogram 3), который записывает школьников 8–11 классов на спортивные секции.
Все данные хранятся в Google-таблице: лимиты, дедлайн, реестр учеников и списки по секциям.
Интерфейс на русском и казахском языках.

## Возможности

- Регистрация: язык → имя → класс → телефон (только через кнопку «Отправить номер») → проверка данных.
- На каждом шаге есть кнопка «← Назад», в любой момент можно начать заново (`/start`, `/cancel`, кнопка «🔄 Начать заново»).
- Выбор секции с учётом лимитов по группам классов (8–9 и 10–11), защита от гонки при одновременной записи.
- Просмотр и отмена своей записи, дедлайн записи из таблицы.
- Админ-команды: сводка по секциям, аналитика по классам, напоминание ученикам без секции, выгрузка в `.xlsx`, сброс кэша.

## 1. Создание бота в @BotFather

1. Открой [@BotFather](https://t.me/BotFather), отправь `/newbot`.
2. Укажи название (например, `Beta High School Sport`) и username (должен заканчиваться на `bot`).
3. Скопируй выданный токен вида `123456789:AAH...` — он пойдёт в `BOT_TOKEN`.

## 2. Google Cloud и сервисный аккаунт

1. Зайди в [Google Cloud Console](https://console.cloud.google.com/) и создай новый проект.
2. В меню «APIs & Services → Library» включи два API:
   - **Google Sheets API**
   - **Google Drive API**
3. В «APIs & Services → Credentials» нажми «Create credentials → Service account».
   Задай любое имя, роли можно не выбирать, заверши создание.
4. Открой созданный сервисный аккаунт → вкладка «Keys» → «Add key → Create new key → JSON».
   Скачается JSON-файл.
5. Сохрани его в корень проекта под именем `credentials.json`.
6. Запомни email сервисного аккаунта (поле `client_email` в JSON, вида `name@project.iam.gserviceaccount.com`).

## 3. Google-таблица

1. Создай новую Google-таблицу.
2. Нажми «Настройки доступа» и добавь email сервисного аккаунта с правами **Редактор**.
3. Скопируй ID таблицы из адресной строки: `docs.google.com/spreadsheets/d/<ЭТО_ID>/edit` — он пойдёт в `SPREADSHEET_ID`.
4. Создай три листа с точными названиями:

### Лист `Настройки`

Пары ключ-значение: колонка A — ключ, колонка B — значение.

| A | B |
|---|---|
| deadline | 2026-09-30 18:00 |

`deadline` — дата и время закрытия записи в формате `YYYY-MM-DD HH:MM` по времени Asia/Almaty.
Если ячейка пустая — дедлайна нет.
Чтобы Google Sheets не переформатировал дату, введи значение с апострофом в начале (`'2026-09-30 18:00`)
или задай ячейке формат «Обычный текст».

### Лист `Лимиты`

Первая строка — заголовки, далее по одной строке на секцию. Список секций берётся только отсюда.
Лимиты задаются по группам классов: `8-9` (8 и 9 классы) и `10-11` (10 и 11 классы).

| Секция | 8-9 | 10-11 |
|---|---|---|
| Футбол | 10 | 10 |
| Баскетбол | 8 | 8 |
| Волейбол | 8 | 8 |
| Настольный теннис | 6 | 4 |
| Шахматы | 6 | 6 |
| Регби |  | 12 |

Правила:
- общий лимит секции = `8-9` + `10-11`;
- ученик 8 или 9 класса занимает место в группе `8-9`, ученик 10 или 11 класса — в группе `10-11`;
- если лимит группы пустой или `0`, ученики этой группы секцию не видят вообще (в примере «Регби» доступно только 10–11 классам);
- если пусто в обеих группах — секция никому не показывается, лист для неё не создаётся;
- пробелы в числах допустимы, пустая ячейка = нет мест для группы.

### Лист `Ученики`

Можно оставить пустым — бот сам впишет заголовки при первом запуске:

`tg_id | Имя | Класс | Телефон | Язык | Секция | Дата записи | Дата регистрации`

`Дата регистрации` ставится при первом сохранении ученика и при перерегистрации не меняется.
`Дата записи` — дата выбора секции. Если в таблице уже есть ученики без даты регистрации, они считаются
зарегистрированными «давно» и попадают только в аналитику за всё время.

### Лист `Аналитика`

Создаётся ботом автоматически, руками создавать и редактировать не нужно: бот полностью перезаписывает его
при старте, после каждой регистрации, записи и отмены, а также по команде `/reload`. Содержимое:

- «Обновлено: ДД.ММ.ГГГГ ЧЧ:ММ» и «Самый пассивный класс за 7 дней»;
- четыре таблицы `Класс | Зарегались | Записались | Без секции` со строкой «Итого»: **Сегодня**, **Вчера**, **7 дней**, **Всё время**;
- блок «По дням» за последние 14 дней: `Дата | 8 кл | 9 кл | 10 кл | 11 кл | Всего` (регистрации).

Периоды считаются по колонке «Дата регистрации» листа «Ученики» (время Asia/Almaty). Ученики без этой даты
попадают только в таблицу «Всё время».

### Листы секций

Для каждой секции из `Лимиты` бот при старте создаёт лист с тем же названием и заголовками
`Имя | Класс | Телефон | tg_id | Дата записи`. Создавать их вручную не нужно.
Если добавишь новую секцию в `Лимиты` — перезапусти бота (или создай лист вручную с такими же заголовками) и отправь `/reload`.

## 4. Установка

Нужен Python 3.11 или новее.

```bash
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

## 5. Настройка `.env`

```bash
cp .env.example .env
```

Заполни переменные:

```
BOT_TOKEN=123456789:AAH...            # токен от @BotFather
SPREADSHEET_ID=1AbCdEf...             # ID из URL таблицы
ADMIN_IDS=111111111,222222222         # tg_id админов через запятую (узнать у @userinfobot)
GOOGLE_CREDENTIALS_PATH=credentials.json
```

## 6. Запуск

```bash
python main.py
```

При старте бот проверит наличие листов `Настройки`, `Лимиты`, `Ученики` и создаст недостающие листы секций.
Логи пишутся в stdout.

## 7. Деплой на Railway

Бот работает через polling, поэтому публичный домен и порт не нужны — достаточно сервиса типа worker.

1. Залей проект в GitHub-репозиторий. Файлы `.env` и `credentials.json` в репозиторий не попадают (они в `.gitignore`), их содержимое передаётся через переменные окружения.
2. На [railway.app](https://railway.app) нажми «New Project → Deploy from GitHub repo» и выбери репозиторий.
   Railway найдёт `Procfile` (`worker: python main.py`) и `requirements.txt`, версия Python берётся из `runtime.txt` / `.python-version` (3.12).
3. Во вкладке «Variables» сервиса добавь переменные:

   | Переменная | Значение |
   |---|---|
   | `BOT_TOKEN` | токен от @BotFather |
   | `SPREADSHEET_ID` | ID таблицы |
   | `ADMIN_IDS` | tg_id админов через запятую |
   | `GOOGLE_CREDENTIALS_JSON` | содержимое `credentials.json` одной строкой |

   Однострочный JSON для `GOOGLE_CREDENTIALS_JSON` можно получить так:

   ```bash
   python -c "import json; print(json.dumps(json.load(open('credentials.json'))))"
   ```

   Скопируй вывод целиком, включая фигурные скобки. `GOOGLE_CREDENTIALS_PATH` на Railway не нужен: если задана `GOOGLE_CREDENTIALS_JSON`, файл не читается.
4. Нажми «Deploy». В логах сервиса должно появиться `Бот запущен, админы: [...]`.
5. Запускай ровно один экземпляр бота: два одновременных polling-процесса с одним токеном конфликтуют (Telegram отвечает ошибкой `Conflict: terminated by other getUpdates request`). Перед деплоем на Railway останови локальный `python main.py`.

`railway.json` задаёт команду запуска и перезапуск при падении (до 10 попыток).

## 8. Команды

### Для ученика

| Команда | Что делает |
|---|---|
| `/start` | Регистрация (язык → имя → класс → телефон → проверка данных) или показ текущей записи / списка секций. В любом состоянии сбрасывает незавершённую регистрацию |
| `/my` | Показать свою запись и кнопку отмены; если записи нет — список секций |
| `/lang` | Сменить язык интерфейса (русский / қазақша) |
| `/cancel` | Начать заново: сброс состояния → выбор языка → имя → класс → телефон. Для уже зарегистрированного ученика обновляет его строку в «Ученики», секция при этом сохраняется |

Кнопки «Назад»:
- на шаге **имя** — reply-кнопка «← Назад» возвращает к выбору языка;
- на шаге **класс** — «← Назад» под кнопками 8/9/10/11 возвращает к вводу имени (текущее имя показывается в подсказке);
- на шаге **телефон** — «← Назад» под кнопкой «📱 Отправить номер» возвращает к выбору класса;
- на экране **проверки данных** — «✏️ Изменить» возвращает к вводу имени (класс и телефон вводятся заново);
- под **списком секций** — «← Назад» возвращает к экрану проверки данных, «🔄 Начать заново» сбрасывает всё;
- на экране **подтверждения записи** — «✏️ Изменить данные» (секция запоминается, после проверки данных снова показывается этот экран) и «↩️ Другая секция».

Во время регистрации команды `/my` и `/lang` не работают: бот просит закончить регистрацию или нажать `/start`.

Правила записи:
- одна секция на ученика; чтобы сменить секцию, сначала отмени текущую запись;
- место доступно, если не исчерпан общий лимит секции и лимит для класса ученика;
- после дедлайна запись и отмена недоступны.

### Для админа (только tg_id из `ADMIN_IDS`, остальным команды не отвечают)

| Команда | Что делает |
|---|---|
| `/stats` | Сводка по секциям: `Футбол: 12/20 (8-9кл 7/10, 10-11кл 5/10)`, всего зарегистрировано/записано, дедлайн |
| `/analytics` | Аналитика по каждому классу 8–11 за всё время: зарегались / записались / без секции, самый пассивный класс, регистрации по дням. Те же цифры всегда есть на листе «Аналитика» в таблице |
| `/analytics N` | То же за последние N дней (1–365) по дате регистрации, например `/analytics 7` |
| `/remind 9` | Напомнить всем ученикам 9 класса без секции (на их языке), после подтверждения кнопкой. `/remind all` — всем классам. В конце отчёт «Отправлено / не доставлено» |
| `/export` | Файл `sections_YYYY-MM-DD_HH-MM.xlsx`: лист `Сводка` (`Секция | Записано | 8-9 | 10-11`, в группах `записано/лимит`) + лист на каждую секцию |
| `/reload` | Сбросить кэш лимитов и настроек (иначе изменения в таблице подхватятся в течение 60 секунд) и пересчитать лист «Аналитика» |

Меню команд в Telegram у админов (по их tg_id) содержит и админские команды, у учеников — только `/start`, `/my`, `/lang`, `/cancel`.

**Важно про `/remind`:** бот физически может написать только тем, кто хотя бы раз нажал `/start` (есть строка в «Ученики»).
Ученикам, которые ещё не открывали бота, ссылку на него нужно отправить в чат класса вручную.
Если ученик заблокировал бота, он попадает в «не доставлено».

## Как это работает внутри

- Лимиты и настройки кэшируются на 60 секунд, записи читаются всегда из таблицы.
- Место в секции доступно, если число записанных из группы ученика (`8-9` или `10-11`) меньше лимита группы.
- Запись и отмена выполняются последовательно под `asyncio.Lock`; перед добавлением строки лимиты проверяются повторно по свежим данным, поэтому два ученика не займут одно последнее место.
- Время — `Asia/Almaty`, даты записи в формате `DD.MM.YYYY HH:MM`.
- Любая ошибка Google API логируется с traceback, пользователь видит «Что-то пошло не так, попробуй позже».
